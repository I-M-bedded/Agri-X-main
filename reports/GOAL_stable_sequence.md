# [GOAL] 시작 위치가 변해도 복귀까지 안정적인 시퀀스

센서 구성: **엔코더 + 비전 + 1D ToF ×2** (IMU 없음).
밭은 직사각형, 로봇은 헤드랜드 근방 어딘가에서 **밭쪽을 보고** 출발하되
**시작 위치는 매번 달라진다**(0번 팻말에서 멀지 않음).

이 문서는 목표(GOAL)와, 거기 도달하기 위해 현재 스택에서 바꿔야 할 것을
정리한다. 모든 수치는 `reports/sim_closed_loop_report.md` 의 실측이다.

| 지표 | 값 |

## 1. IMU 없는 구성의 근본 제약 ★

회전각은 엔코더로만 잰다. 궤도는 회전 시 지면을 비비므로 미끄러짐이 누적되고,
**로봇은 자기가 틀렸다는 것조차 모른다.** IMU가 없으면 절대 방위를 줄 수 있는
것은 **마커뿐**이다.

코드에는 이미 IMU-free 절대 방위 수단이 있다:

> `_reanchor_heading_from_posts()` — 팻말 **2개가 동시에 보이면** 두 점을 잇는
> 선이 곧 헤드랜드 방향. 마커의 **위치**만 쓰므로 포즈 모호성이 없다.

**문제: 이 함수가 거의 발동하지 않는다 (관측 기회 1%).**
- 원래 HOME 복귀 경로에서만 호출됐다 → 급수 주행 내내 보정 0회
- 탐색 단계에도 연결해 봤으나(적용함), 입구에서는 **화각 62° 안에 팻말이
  하나만** 들어와 여전히 발동하지 못한다

→ **이것이 목표 달성의 핵심 병목이다.**

## 2. 시도했고 **효과 없었던** 것 (재시도 방지용 기록)

| 시도 | 결과 | 판정 |
|---|---|---|
| 고랑당 팻말 2개(좌우 0.6m) | 완주 66% → **50%** | ✗ 기각 |
| 팻말 이랑에 평행(90°) | 완주 → **0%** (정면 진입 불가) | ✗ 기각 |
| 팻말 60° | 완주 → **0%** | ✗ 기각 |
| 밭 방위 재기준 상한(25°) | 변동 시작 66% → **52%** | ✗ 기본 비활성 |
| 마커 검출거리 3→8m | 66% → 66% (변화 없음) | ✗ 무효 |
| 직선(creep) 우선 탐색 | 66% → **26%** | ✗ 기각 |
| 회전 후 직선(2단계) | 66% → 59% | △ 옵션 유지 |

**짝 팻말이 실패한 이유**: 팻말이 2배가 되면 목표 팻말(2k) 옆에 다른 팻말
(2k−1)이 더 가까이 보여 정렬 대상이 흔들린다. 방위 보정 기회는 1%→3% 로
거의 늘지 않았는데, 정렬은 확실히 나빠졌다. **얻는 것보다 잃는 것이 크다.**

## 3. 시도했고 **효과 있었던** 것 (이미 적용)

| 변경 | 효과 |
|---|---|
| `SEARCH_MODE = "rotate"` | 변동 시작 26% → **66%** |
| `START_LOCALIZE_FROM_MARKER` | 16% → 26% (rotate 와 합쳐 66%) |
| ToF 거부권 `VISION_TOF_DISAGREE_LIMIT=0.15` | 고정 시작 6.7% → **80%**, 이랑밟음 30/30 → **0/30** |
| 비전 신뢰도 비례 가중치 | 단독 효과 미미, 거부권과 함께 사용 |
| 고랑 폭 40cm (`TOF_NOMINAL...=200`) | 좌우 여유 5cm → **10cm** |

핵심 교훈 2개:
1. **confidence 로는 비전 오답을 못 거른다** (오답의 conf 가 오히려 높다).
   물리량을 재는 **ToF 교차검증만이** 거른다.
2. 팻말은 전부 헤드랜드선에 있고 로봇은 밭쪽을 본다 → **직선 전진 탐색은
   마커에서 멀어진다.** 회전이 맞다(면각은 위치로만 정해지지만, 시작 시
   실패는 대개 화각 문제이고 화각은 회전으로 해결된다).

## 4. 제안하는 목표 시퀀스

```text
[출발] 헤드랜드 근방, 밭쪽 응시, 위치는 변동
   │
① 제자리 회전 탐색 (SEARCH_MODE="rotate")
   │  ├─ 보이는 팻말로 **시작 고랑 번호 확정** (START_LOCALIZE_FROM_MARKER)
   │  └─ 팻말 2개 보이면 밭 방위 절대 보정
   ▼
② 마커 앞 정렬 → 진입각 보정
   ▼
③ 고랑 주행: 비전(신뢰도 비례) + ToF 거부권 + 엔코더 헤딩 폴백
   ▼ 좌우 ToF 벽 소실
④ 유턴 → ⑤ 복귀 주행 → ⑥ 이탈
   ▼
⑦ 다음 고랑: 헤드랜드 이동 → ① 반복
   ▼ END 마커 확인 / 물 부족
⑧ HOME 복귀: 칸 수 계산 + 정거장마다 마커 1회 훑어 절대 보정
```

|---|---:|---:|
| 시작 위치 변동 완주율 | 66% | **≥ 90%** |
| 이랑 밟음 | 0/30 | 0 유지 |
| 고랑 내 최악 횡편차 | 9.2cm | ≤ 10cm 유지 |

## 5. 현재 스택에서 바꿔야 할 것 (우선순위)

### P1 — 진입 시 **횡 정렬** (실측으로 확인된 진짜 병목) ★

실패 14/42건의 사유를 분해한 결과:

| 사유 | 건수 | 완료 고랑 |
|---|---:|---:|
| **"3초 안에 좌우 이랑 벽 미감지"** | **6** | **0** |
| 다음 팻말(id=2) 탐색 실패 | 3 | 1~3 |
| 탐색 타임아웃 | 3 | — |
| 비전 신뢰도 20초 부족 | 1 | — |
| HOME 팻말 탐색 실패 | 1 | — |

**최대 원인은 "정렬은 했는데 고랑이 아닌 곳으로 진입"** 이다(완료 고랑 0).
팻말은 중심선이 아니라 **이랑 위(0.3m 옆)** 에 있으므로, 팻말 방위로
접근하면 이랑을 향한다. 시작 위치가 고랑 중심에서 벗어날수록 심해진다.

- 즉효 처방: `FURROW_WALL_ACQUIRE_SEC` 3.0 → **3.5** (적용).
  6.0 이면 완주 71% 까지 오르지만 **4.0 이상에서 "ToF 고장 시 정지" 안전
  테스트가 깨진다**(센서가 죽었는데 벽 없이 완주해 버림). 안전 우선.
- 근본 처방: 벽 미감지 판정을 **시간이 아니라 주행 거리** 기준으로 바꾸고,
  진입 전 ToF 탐침으로 **횡 정렬을 확실히 끝낸 뒤** 진입하도록 강화.

### P1-보류 — 방위 보정 기회 늘리기 (**측정 결과 효과 없음**)

IMU 가 없으니 2-팻말 절대 방위 보정이 핵심일 것이라 보고 세 가지를 시험했으나
**전부 완주율을 못 올렸다.** 재시도 방지를 위해 기록한다:

| 시도 | 2팻말 동시관측 | 완주 |
|---|---:|---:|
| 기준 | 1% | 66% |
| 탐색 단계에서도 보정 호출 (적용) | 1% | 66% |
| 헤드랜드 이동 중 보정 (`HEADLAND_ANCHOR_HEADING`, 적용) | 1% | 66% |
| 마커 검출거리 3→8m | 1% | 66% |
| 카메라 화각 62°→90° | 3% | 64% |
| 카메라 화각 62°→120° | 8% | 59% |
| 카메라 화각 62°→150° | 10% | 59% |

**화각을 넓혀 관측 기회를 10배로 늘려도 완주율은 오히려 떨어진다.**
→ 방위 드리프트는 이 규모(고랑 3개)에서 지배적 실패 원인이 아니다.
   광각 카메라로 바꿀 근거가 없다. 고랑 수가 훨씬 많은 밭에서 재평가할 것.

### P1-완료 — 벽 미감지를 **거리 기준**으로 (적용)

시간 기준만 쓰면 두 요구가 충돌했다: 유예를 늘려야 변동 시작을 견디는데,
4초 이상이면 "ToF 고장 시 정지" 안전 테스트가 깨졌다(센서가 죽었는데 벽 없이
완주). **거리 기준을 병행하니 충돌이 사라졌다.**

| 시간 / 거리 | 완주 | ToF고장 안전테스트 |
|---|---:|---|
| 3.5초 / 없음 | 66% | PASS |
| 6초 / 없음 | 71% | **FAIL** |
| 6초 / 0.6m | 64% | PASS |
| **6초 / 1.0m** | **69%** | **PASS** ★채택 |
| 6초 / 1.5m | 71% | **FAIL** |

`FURROW_WALL_ACQUIRE_SEC=6.0` + `FURROW_WALL_ACQUIRE_MAX_TRAVEL_M=1.0`.
둘 중 먼저 걸리는 쪽에서 SAFE_HALT.

**ToF 는 진입 첫 틱부터 매 틱 읽는다**(`line_follower.step()` 안에서).
위 유예값은 '언제부터 보는가'가 아니라 '언제 포기하는가'다.

### P1-완료 — 팻말 각도로 밭 방위 유도 (적용, 효과는 중립)

예전에는 팻말의 자세(yaw)를 "노이즈가 크다"며 버리고, 밭 방위를
**출발 시 로봇이 향한 방향**으로 가정했다. 카메라 캘리브레이션을 전제로
팻말 하나만 보고 밭 방위를 유도하도록 바꿨다:

```
F = theta + b - yaw - tilt
  theta: 오도메트리 헤딩, b: 팻말 베어링(CCW+),
  yaw: 관측 마커 yaw, tilt: 설치 각도(로봇이 안다)
```

- **정확도: odom 프레임에서 오차 0.00°** (시뮬 참값 대조 검증)
- 팻말 **1개**면 되므로 2개가 필요한 `_reanchor_heading_from_posts` 보다
  훨씬 자주 쓸 수 있다
- **효과는 중립**: 시작 헤딩이 정확할 때(운용 조건) 무효(69%→69%),
  틀어졌을 때는 방향에 따라 갈린다(120° 50%→83%, 60° 83%→66%).
  이유 추정: 방위가 정확해지면 진입각 게이트가 비스듬한 접근을 **올바르게
  거부**해 완주율이 내려간다. 완주율만으로 판단하면 안 되는 사례.
- 유지하는 이유: 수식이 정확하고, "로봇이 밭쪽을 보고 출발해야 한다"는
  가정을 제거하는 올바른 구조다. `USE_MARKER_TILT_FOR_FIELD_HEADING=False`
  로 끌 수 있다.

### 파일럿 결론 — 설계 확정 (A vs B, IMU 유무)

실용 팻말 각도(0/30°) × IMU 유무 × 미끄러짐(0/3%), **셀당 42시행**:

| 축 | 완주 | 유턴+복귀 | HOME중앙 |
|---|---:|---:|---:|
| **A 측량기반** | 67.3% | 83.9% | 23.8cm |
| **B 측량무관** | 63.7% | 82.4% | **17.9cm** |
| IMU 없음 | 62.5% | 80.1% | 24.5cm |
| **IMU 있음** | **68.5%** | **86.3%** | **17.2cm** |

최악 조건(3% 미끄러짐 + IMU 없음): A 완주 54.8%/HOME 50.8cm,
B 완주 56.0%/HOME 37.5cm.

**결론 1 — 설계는 B(측량 무관)로 확정.** A 가 완주에서 +3.6%p 앞서지만 B 가
HOME 정확도에서 앞서고 최악 조건에서는 B 가 근소 우위다. **차이가 통계적으로
구분되지 않으므로**, 설치 오차에 강건하고 기존 안전 원칙을 지키는 B 를 택한다.
(`MARKER_ON_RIDGE_CENTER=True` 로 A 전환 가능, 코드 경로는 남겨 둠)

**결론 2 — IMU 는 명확한 이득.** 특히 **유턴+복귀 성공률 80.1% → 86.3%**,
HOME 오차 24.5 → 17.2cm. "IMU 없음" 제약을 유지하면 유턴+복귀가 **5회 중
1회꼴로 실패**한다(최악 조건 70%). 이 수치를 감수할지가 하드웨어 결정 사항.

### ★ 2D 시뮬의 한계가 결론을 뒤집은 사례 — 마커 yaw

`USE_MARKER_TILT_FOR_FIELD_HEADING`(팻말 각도로 밭 방위 유도)은 시뮬에서
**오차 0.00°** 로 검증됐으나, **실기에서는 성립하지 않아 기각**했다.

`tools/aruco_angle_bench.py` 로 실제 OpenCV 검출기를 돌린 결과:

| 마커 / 거리 | 사다리꼴 좌우변 차이 | 추정 yaw (참값) |
|---|---:|---|
| 10cm / 2.0m | **0.00px** | 0° (30°) — 원근 단서 없음 |
| 10cm / 1.0m | 3~4px | **−149°** (30°) |
| 20cm / 0.5m | 76px (충분) | **−119.7°** (60°) |

**단서가 충분해도 틀린다.** 평면 마커의 포즈 모호성(IPPE 가 두 해를 내놓고
틀린 쪽이 선택됨) 때문이며 캘리브레이션으로 해결되지 않는다.

**왜 시뮬이 놓쳤나**: 시뮬은 마커 yaw 를 **참값 그대로** 넘겨줬다. 그래서
"오차 0.00°"는 순환 검증이었다. 시뮬이 모델링하지 않는 항목(포즈 모호성)이
실기의 지배적 오차원이었다.

→ 밭 방위가 필요하면 **팻말 2개의 위치**를 쓰는 `_reanchor_heading_from_posts`
를 쓸 것(위치만 쓰므로 모호성 무관). 저장소의 원래 설계가 옳았다.

### P2 — HOME 복귀 말단 회귀 수정

`SEARCH_MODE=rotate` 로 바꾸며 selftest 의 "미끄러짐 2% + 고랑 12개" 가
실패한다(142/146). **12개 고랑 급수는 전부 성공**하고 HOME 주차만 2.03m
벗어난다. creep 이 있을 때는 통과했다.
→ **HOME 복귀 말단에서만 creep 을 허용**하는 절충(상태별 탐색 모드).

### P3 — 카메라 캘리브레이션

`CAMERA_MATRIX = None`, 틸트각 미정. 이 때문에 시뮬의 `furrow_scale` 이
가정값이다(결론은 4배 범위에서 불변임을 확인했으나, 정밀도가 필요해지면 필수).

### P4 — 운용 제약 문서화

- 로봇은 **밭쪽을 보고** 출발할 것 (헤드랜드를 보고 출발하면 팻말 각도와
  무관하게 완주 0%)
- 0번 팻말에서 **±0.4m 이내** 권장 (그 밖에서는 완주율이 급락)
- 팻말 기울기 **10~30°**, 전부 END 방향 (45° 이상은 정면 진입 실패)

## 6. 열/행 진입 (직사각형 밭)

현재 코드는 **한 축(고랑 방향)만** 다룬다. 행/열을 바꿔 진입하려면
`_field_heading` 기준을 90° 돌린 두 번째 미션으로 재실행하는 것이 가장 싸고
안전하다(코드 변경 없음). 한 번의 임무 안에서 축을 바꾸는 것은
헤드랜드 이동 로직 전체가 축에 묶여 있어 권하지 않는다.
