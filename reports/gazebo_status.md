# Gazebo 물리 시뮬 — 구축 현황 및 실측 결과

2026-09-01. 2D 시뮬이 답하지 못한 것(마커 실제 검출, 충돌, ToF 반사)만 좁게 본다.

## 확정된 밭 배치 규약 ★

```
[이랑0+마커0] [고랑1] [이랑1+마커1] [고랑2] [이랑2+마커2] ...
```
- 마커 k = **이랑 k 중심**:  x = (k − 0.5) × 간격 → −0.5, 0.5, 1.5, 2.5, 3.5
- 고랑 k = 이랑 k−1과 이랑 k **사이**: x = 0, 1, 2, 3
- **마커 0의 이랑을 지나쳐야 첫 진짜 고랑(고랑 1)**. 마커 0은 HOME 기준점일 뿐
  진입 지점이 아니다.

이전에는 마커를 −0.7/0.3/1.3 에 두고 마커 0 왼쪽에 **엉뚱한 고랑**을 하나 더
만들어 놨었다. 여분 이랑을 제거하고 규약을 통일했다.

## 실측 결과

### ArUco 검출 — 기본 설정으로는 **0건**이었다

| 문제 | 원인 | 조치 |
|---|---|---|
| 마커가 새까맣게 렌더 | PBR **metalness 기본값 1.0** | metalness 0 / roughness 1 |
| 흰 셀이 어두운 회색 | 조명 부족 | 환경광 0.75 + 정면 보조광 |
| **검출 0건** | **해상도** (10cm@2.1m ≈ 25px) | 검출기 파라미터 튜닝 |

2배 확대하면 검출되고 좌우/상하 반전은 모두 실패 → **텍스처 문제가 아니라
순수 픽셀 부족**이 원인이었다. 저장소 `aruco_detector.py`에 반영:
`minMarkerPerimeterRate=0.01`, `perspectiveRemovePixelPerCell=8`,
`polygonalApproxAccuracyRate=0.05`, `adaptiveThreshWinSize 3~15`.
→ selftest 141 → **143/146**

**현재 상태**: 시작 위치 x=−0.85 에서 **마커 0 검출 성공**.
단, x=−1.2 에서는 마커 0 이 35° 오프축이라 화각(±31°) 밖 → **미검출**.
즉 회전 탐색이 필요하다는 2D 결론과 일치한다.

### ToF — 좌우 양쪽 벽을 정확히 읽는다

고랑 1 중심(x=0)에 놓고 주행:

| 월드 x | 좌 ToF | 우 ToF | 좌+우 |
|---:|---:|---:|---:|
| +0.034 | 0.195 | 0.125 | 0.320 |
| +0.057 | 0.206 | 0.092 | 0.298 |
| −0.069 | 0.080 | 0.218 | 0.298 |

**좌+우 합이 0.30m 로 일정** — 기하학적으로 정확하다(센서 ±0.13m, ToF 높이
8cm 에서 이랑 경사면까지 0.28m → 0.15m씩). 좌우 비대칭은 센서 버그가 아니라
**실제 주행 드리프트**(±0.07m)이며, 제어가 잡아야 할 대상이다.

## 이 과정에서 잡은 버그 (2D 시뮬로는 못 잡는 것들)

1. **차체 절반이 지면에 묻힘** — base_link 높이를 바퀴 반지름(3.3cm)으로 잡아
   50cm 상자 중심이 z=5.3cm 에 놓였다.
2. **로봇이 반대로 주행** — 바퀴를 roll +π/2 로 눕혔는데 조인트 축을 +y 로 둬서
   전진 명령에 후진했다(월드 y −1.1 → −5.49). 축을 −y 로 수정.
3. **이랑에 충돌이 아예 없었음** — 메시에 법선(vn)이 없어 DART 가 충돌 서브메시를
   통째로 무시했다. 그대로 뒀으면 "이랑 충돌 없이 주행" 검증이 무의미했다.
4. **경사면이 고랑 방향으로 누움** — 어깨를 X축(roll)으로 회전시킴. 사다리꼴
   프리즘 메시로 교체해 회전 자체를 없앴다.
5. **post_249 중복 생성** → 월드 로드 실패.
6. **마커 겹침** — HOME과 1번을 같은 좌표에 두면 화면에서 겹쳐 그려져 서로의
   패턴을 망가뜨린다(실기에서도 같은 팻말에 두 장을 겹쳐 붙이면 안 된다).

## 남은 한계
