# 배선 도면 — 핀 번호 전체

`config.py` 최신본 기준입니다. 코드에서 뽑은 값이므로 `config.py` 를 고치면
이 문서도 같이 고치세요.

- 핀 번호는 **BCM**(GPIO 번호) 기준입니다. 코드가 `GPIO.setmode(GPIO.BCM)` 을
  씁니다. 아래 표에 40핀 헤더의 **물리 핀 번호**를 같이 적어 두었습니다.
- 라즈베리파이 GPIO 는 **3.3V 전용**입니다. 5V 신호를 직접 물리면 핀이
  타거나 Pi 가 죽습니다. 센서 모듈 전원을 3.3V 로 주는 것이 가장 안전합니다.

---

## 1. 핀 배정 한눈에 보기

| 기능 | config 키 | BCM | 물리핀 | 방향 | 비고 |
|---|---|---|---|---|---|
| Mega 제어 링크 | `SERIAL_MEGA_PORT` | — | USB | 양방향 | `/dev/ttyACM0`, 115200 |
| 펌프 스위치 | `PUMP_RELAY_PIN` | **26** | 37 | OUT | HIGH = ON (아래 §5) |
| 좌 ToF XSHUT | `TOF_LEFT["xshut_pin"]` | **17** | 11 | OUT | |
| 우 ToF XSHUT | `TOF_RIGHT["xshut_pin"]` | **27** | 13 | OUT | |
| I2C SDA | (고정) | **2** | 3 | — | ToF 2개 공통 |
| I2C SCL | (고정) | **3** | 5 | — | ToF 2개 공통 |
| 수위 센서 | `WATER_LEVEL_SENSOR_PIN` | **22** | 15 | IN | 내부 풀다운 |
| 카메라 | `CAMERA_INDEX = 0` | — | — | — | GPIO 아님. CSI 리본 |

**쓰는 전원 핀**

| 용도 | 물리핀 |
|---|---|
| 3.3V (센서 전원) | 1, 17 |
| GND | 6, 9, 14, 20, 25, 30, 34, 39 |

5V 핀(2, 4)은 **쓰지 마세요.** 모터·펌프 전원을 여기서 뽑으면 기동 전류로
전압이 주저앉아 Pi 가 리부팅되거나 SD카드가 깨집니다.

**비어 있는 핀** — GPIO 4, 7, 8, 9, 10, 11, 14, 15, 16, 18, 19, 25.
나중에 IMU(알려진 한계 3번)를 붙이면 I2C 를 그대로 공유하면 됩니다.

## 2. 전원 계통 (12V 배터리 → 3갈래)

```
        ┌──────────────┐
        │  12V 배터리   │
        └──┬───┬────┬──┘
           │   │    │
   ┌───────┘   │    └────────────┐
   │           │                 │
┌──▼────────┐ ┌▼──────────────┐ ┌▼─────────────┐
│ 벅컨버터   │ │ 모터 드라이버  │ │ LR7843 N-MOS │
│ 12V → 5V  │ │  VM = 12V     │ │  V+ = 12V    │
│  3A 이상  │ │               │ │              │
└──┬────────┘ └───────┬───────┘ └──────┬───────┘
   │ 5V/GND           │ 좌우 모터       │ 워터펌프
┌──▼────────┐         ▼                ▼
│ 라즈베리파이│
│  pin 2/4  │  ←  5V
│  pin 6    │  ←  GND
└───────────┘

★ 모든 GND 를 한 점에서 공통으로 묶으세요 (Pi GND 포함).
  GND 가 안 묶이면 신호 기준이 달라져서 ToF 가 튀거나
  모터가 제멋대로 돕니다.
```

**주의**

- 벅컨버터는 **3A 이상**을 쓰세요. Pi4 + 카메라가 순간 2.5A 를 먹습니다.
- 모터 드라이버(L298N)에 붙은 5V 출력 단자로 Pi 를 먹이지 마세요. 용량이
  모자라고 모터 노이즈가 그대로 올라탑니다.
- 배터리와 각 분기 사이에 퓨즈를 넣으면 좋습니다.
- 배선 순서: **GND 먼저 → 신호선 → 마지막에 전원**. 반대로 하면 GND 가
  안 잡힌 상태에서 신호선을 통해 전류가 흘러 소자가 죽습니다.

## 3. Arduino Mega + BTS7960 모터 드라이버

라즈베리파이는 모터 GPIO를 직접 구동하지 않고 Mega와 USB로만 연결합니다.
아래 핀은 `agrix_motor_mega.ino`의 현재 핀맵입니다.

| 기능 | Arduino Mega 핀 | 연결 |
|---|---:|---|
| 좌 BTS7960 RPWM | **D6** | Motor 1 RPWM |
| 좌 BTS7960 LPWM | **D7** | Motor 1 LPWM |
| 우 BTS7960 RPWM | **D44** | Motor 2 RPWM |
| 우 BTS7960 LPWM | **D45** | Motor 2 LPWM |
| 좌 엔코더 A/B | **D2 / D3** | Motor 1 encoder A/B |
| 우 엔코더 A/B | **D18 / D19** | Motor 2 encoder A/B |
| 통신 | **USB-B** | Pi USB, `/dev/ttyACM0`, 115200 |

- 각 BTS7960의 `R_EN`과 `L_EN`은 HIGH로 유지합니다.
- Mega GND, 두 BTS7960 GND, 12V 배터리 GND를 공통으로 묶습니다.
- RPWM과 LPWM을 동시에 활성화하지 않으며 펌웨어가 20kHz PWM을 만듭니다.
- 논리상 전진 부호는 펌웨어의 `MOTOR1_FORWARD_SIGN`과
  `MOTOR2_FORWARD_SIGN`에서 보정합니다.
- `actuators/motor_driver.py` 핀맵은 Gazebo/내부 시뮬레이션용이며 실기
  배선 기준이 아닙니다.

## 4. ToF ×2 (VL53L1X)

**전원·I2C 는 공통, XSHUT 만 따로** 뺍니다.

| VL53L1X 단자 | 좌 센서 | 우 센서 |
|---|---|---|
| VIN | 3.3V (pin 1) | 3.3V (pin 1) |
| GND | GND | GND |
| SDA | GPIO2 (pin 3) | GPIO2 (pin 3) |
| SCL | GPIO3 (pin 5) | GPIO3 (pin 5) |
| **XSHUT** | **GPIO17 (pin 11)** | **GPIO27 (pin 13)** |

```
Pi GPIO2 ──┬── SDA (좌)
           └── SDA (우)
Pi GPIO3 ──┬── SCL (좌)
           └── SCL (우)
Pi GPIO17 ──── XSHUT (좌)     ← 따로!
Pi GPIO27 ──── XSHUT (우)     ← 따로!
```

**왜 XSHUT 를 따로 빼나** — VL53L1X 는 공장 출하 주소가 둘 다 `0x29` 입니다.
그냥 붙이면 충돌합니다. `sensors/tof_sensor.py` 의 `ToFPair` 가 부팅할 때
이렇게 처리합니다.

1. XSHUT 둘 다 LOW → 두 센서 모두 끔
2. 좌측만 HIGH → `0x29` 로 접속 → 주소를 **`0x30`** 으로 변경
3. 우측도 HIGH → `0x29` 로 접속 → 주소를 **`0x31`** 로 변경

**확인 방법** — 프로그램이 **돌고 있는 중**에 다른 터미널에서:

```bash
i2cdetect -y 1
```

`30` 과 `31` 두 개가 보여야 정상입니다. `29` 하나만 계속 보이면 XSHUT 배선이
잘못된 것입니다. (프로그램이 꺼진 상태에서는 `29` 만 보이는 게 맞습니다)

**설치 방향** — 좌우 센서를 차체 좌우에 **바깥쪽으로 수평** 을 향하게 답니다.
고랑 안에서 좌우 이랑 벽을 봐야 하고, 정상 주행 시 벽까지 거리가
`TOF_NOMINAL_WALL_DISTANCE_MM = 150mm` 로 잡혀 있습니다. 실제 고랑 폭을
잰 뒤 이 값을 고치세요. 센서를 이랑 **높이 중간**쯤에 오도록 다세요. 너무
높으면 벽을 넘겨다보고, 너무 낮으면 흙에 파묻힙니다.

I2C 풀업은 Pi 보드에 1.8kΩ 이 이미 있습니다. 브레이크아웃마다 붙은
풀업까지 합쳐도 문제없습니다. 선이 20cm 를 넘으면 통신이 불안정해집니다.

## 5. 워터펌프 + LR7843

| LR7843 단자 | 연결 | BCM / 물리핀 |
|---|---|---|
| SIG (PWM/트리거) | 펌프 제어 | **26 / 37** |
| VCC (로직) | 3.3V (pin 1) | — |
| GND (로직) | 공통 GND | — |
| 입력 V+ / V− | 배터리 12V / GND | — |
| 출력 V+ / V− | 워터펌프 | — |

```
GPIO26 ──▶ SIG
                LR7843
12V ──▶ 입력V+  ────────  출력V+ ──▶ 펌프 +
GND ──▶ 입력V−  ────────  출력V− ──▶ 펌프 −
                              ▲
                   플라이백 다이오드 (펌프 양단, 캐소드가 +쪽)
```

**신호 극성**

```python
PUMP_RELAY_ACTIVE_HIGH = True   # HIGH = 펌프 ON
```

LR7843 은 게이트에 HIGH 를 넣으면 도통하므로 `True` 가 맞습니다. 프로그램이
뜨는 순간 GPIO26 이 LOW(=OFF)로 초기화되므로 물이 새지 않습니다.
**active-low 모듈로 바꾸면 반드시 이 값을 `False` 로 고치세요.** 안 그러면
프로그램이 뜨자마자 물이 쏟아집니다.

> **이름 주의** — 상수 이름이 `PUMP_RELAY_PIN` 이지만 실제 하드웨어는
> 릴레이가 아니라 N-MOS 모듈입니다. 코드 동작은 같습니다(디지털 HIGH/LOW).
> 다만 릴레이 모듈용 조언(접점 보호 등)은 해당되지 않고, 대신 **펌프 모터
> 양단에 플라이백 다이오드**를 꼭 다세요. 펌프는 유도성 부하라 끌 때 역기전력이
> 생겨 MOSFET 을 태웁니다. 모듈에 다이오드가 내장돼 있지 않다면 1N5819 나
> 1N4007 을 펌프 양단에 역방향으로 답니다.

펌프에는 3중 인터록이 걸려 있습니다 — 고랑 밖에서는 무조건 OFF, 물 부족 시
잠금, 그리고 `PUMP_MAX_CONTINUOUS_SEC = 120초` 워치독. 고랑 1개 왕복이
120초를 넘으면 이 값을 늘리세요.

## 6. 수위 센서 (TCRT5000)

| 모듈 단자 | 연결 | BCM / 물리핀 |
|---|---|---|
| VCC | **3.3V** (pin 1) | — |
| GND | 공통 GND | — |
| D0 (디지털 출력) | 수위 입력 | **22 / 15** |

> TCRT5000 모듈은 5V 용으로 파는 것이 많습니다. **5V 로 먹이면 D0 출력도 5V**
> 가 되어 Pi 핀이 상합니다. 3.3V 로 먹이세요. 3.3V 에서 감도가 안 나오면
> 분압 저항(예: 10k/20k)을 D0 에 넣고 5V 로 먹이세요.

**신호 극성**

```python
WATER_LOW_SIGNAL_ACTIVE_HIGH = True   # HIGH = 물 부족
WATER_SENSOR_PULL = "down"            # 내부 풀다운
WATER_LEVEL_DEBOUNCE_SEC = 1.0        # 1초 이상 유지돼야 인정
```

풀다운을 거는 이유는, 모듈이 오픈컬렉터 출력이거나 선이 빠졌을 때 핀이 뜬
상태(floating)가 되어 값이 랜덤으로 읽히는 것을 막기 위해서입니다.

> **다만 이 선택에는 대가가 있습니다.** 풀다운이면 신호선이 끊겼을 때 핀이
> LOW = **"물 있음"** 으로 읽힙니다. 즉 배선이 끊기면 로봇은 물이 있다고
> 믿고 빈 펌프를 계속 돌립니다. 랜덤값보다는 낫지만 안전한 쪽으로 실패하는
> 것은 아닙니다. 마지막 방어선은 `PUMP_MAX_CONTINUOUS_SEC = 120초` 워치독
> 하나뿐이므로, **주행 전마다 수위 센서선을 눈으로 확인**하세요.

모듈이 push-pull 출력이면 `WATER_SENSOR_PULL = "off"` 로 둬도 됩니다.
모듈 출력 극성이 반대라면 `WATER_LOW_SIGNAL_ACTIVE_HIGH` 를 `False` 로
뒤집고 `WATER_SENSOR_PULL` 을 `"up"` 으로 바꾸세요. 어느 쪽이든
`tools/setup.py` 1번에서 물통을 실제로 비워 보며 확인해야 합니다.

센서는 물통 **바닥이 아니라 "이제 슬슬 채워야 하는 높이"** 에 답니다.
바닥에 달면 물이 완전히 떨어진 뒤에야 알게 되어 빈 펌프가 돕니다.

## 7. 엔코더 ×2 (Mega 쿼드러처)

| 엔코더 단자 | 좌 | 우 |
|---|---|---|
| VCC | 센서 사양에 맞는 전원 | 센서 사양에 맞는 전원 |
| GND | Mega/드라이버 공통 GND | Mega/드라이버 공통 GND |
| A | Mega **D2** | Mega **D18** |
| B | Mega **D3** | Mega **D19** |

펌웨어는 네 신호를 모두 `CHANGE` 인터럽트로 읽어 x4 디코딩합니다. 현재
JGB3865-520R45-12 가정은 `11 PPR × 45:1 × 4 = 1,980 count/output-rev`입니다.
`STATE`가 보고하는 각도는 이미 좌우 모두 `양수=차체 전진`으로 정규화되어
있으며 Pi 오도메트리는 이 각도 증분을 사용합니다.

## 8. 카메라 (CSI)

GPIO 가 아니라 **CSI 리본 커넥터**입니다. Pi4 의 `CAMERA` 포트(USB 단자 쪽,
`DISPLAY` 포트가 아님)에 꽂습니다. 리본의 **파란 보강판이 USB/이더넷 쪽**을
향하게 합니다.

```python
CAMERA_INDEX = 0
CAMERA_RESOLUTION = (640, 480)
MARKER_SIZE_M = 0.10          # 실제 인쇄한 마커 한 변 길이로 교체
```

카메라 1대가 **ArUco 검출과 흙 색상 비전을 공유**합니다. 그래서 설치 각도가
둘 다를 만족해야 합니다.

- 너무 아래를 보면 팻말 마커를 놓칩니다 (마커는 지면보다 높이 있음)
- 너무 위를 보면 바로 앞 고랑 바닥이 안 보여 중심선 추종이 안 됩니다
- 시작점: 차체 앞쪽, 지면에서 15~25cm 높이, **수평에서 아래로 10~20도**

`tools/setup.py` 1번으로 프레임을 보면서 조정하세요.

`CAMERA_MATRIX` 와 `DIST_COEFFS` 는 `None` 입니다. 이 상태로도 동작하지만
거리 추정 정확도가 떨어집니다. 체스보드 캘리브레이션 값을 넣으면 개선됩니다.

## 9. 배선 후 확인 순서

```bash
python3 selftest.py        # 로직 150/150 (배선과 무관, 먼저 통과시킬 것)
python3 tools/setup.py     # 1 → 2 → 4 → 3 순서
```

| 도구 | 확인 대상 | 모터 도는가 |
|---|---|---|
| 1번 센서 점검 | ToF 2개, 카메라, 수위, 엔코더 | 안 돎 |
| 2번 모터·부호 | `SIGN_*` 9개 | **돎 — 받침대에 띄울 것** |
| 4번 궤도 보정 | `TRACK_SLIP_FACTOR`, 거리 계수 | **돎** |
| 3번 통합 | 전체 | **돎** |

1번에서 걸리는 흔한 문제입니다.

| 증상 | 원인 |
|---|---|
| ToF 가 `0x29` 하나만 | XSHUT 배선 (GPIO17 / 27) |
| ToF 값이 계속 튐 | GND 공통 안 됨, I2C 선이 너무 김 |
| 엔코더 틱 0 | 신호선 오배선, VCC 가 3.3V 아님 |
| 수위가 항상 "부족" | 극성 반대 → `WATER_LOW_SIGNAL_ACTIVE_HIGH` |
| 카메라 프레임 없음 | 리본 방향 반대, `DISPLAY` 포트에 꽂음 |
| 모터가 100% 로만 돎 | L298N ENA/ENB 점퍼 안 뽑음 |
| 모터 전혀 안 돎 | TB6612 STBY 안 올림 |

## 10. 첫 주행 전 안전 점검

- [ ] 모든 GND 가 한 점에서 공통
- [ ] 5V 핀(2, 4)에서 모터·펌프 전원을 뽑지 않음
- [ ] 센서 전원이 전부 3.3V (5V 신호가 GPIO 에 안 들어감)
- [ ] L298N ENA/ENB 점퍼 제거 (또는 TB6612 STBY 를 3.3V 로)
- [ ] 펌프 양단에 플라이백 다이오드
- [ ] `PUMP_RELAY_ACTIVE_HIGH` 가 모듈 극성과 일치 (전원 넣자마자 물이
      안 나오는지 확인)
- [ ] `tools/setup.py` 2번으로 `SIGN_*` 9개 확정
- [ ] `tools/setup.py` 4번으로 `TRACK_SLIP_FACTOR` 실측
- [ ] 물통 비운 상태에서 수위 센서가 "부족"으로 읽히는지 확인

> **장애물 감지 기능이 없습니다.** 사람·동물·돌이 앞에 있어도 모릅니다.
> 첫 주행은 반드시 옆에서 지켜보고, 비상 정지(전원 차단) 수단을 손에
> 들고 계세요.
